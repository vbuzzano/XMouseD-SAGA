## All Findings

### F-01 · CRITICAL · FIXED — Timer loop uninitialized variables
- **File**: src/xmoused.c:785
- **Evidence**: `hadWHActivity`, `hadBTActivity`, `currentWHCounter`, `currentWHDelta`, `currentBTState` declared without initializers, used outside feature-guard `if` branches.
- **Impact**: Undefined behavior (false activity detection, stale last-state writes) when wheel or buttons disabled in config byte.
- **Fix**: Initialized to `FALSE` / `s_lastXxx` / `0` on declaration (2026-06-16). Build verified OK.

### F-02 · MEDIUM · FIXED — TECHNICAL.md GET_STATUS response format wrong
- **File**: docs/TECHNICAL.md:186
- **Evidence**: Documented as `(config << 16) | ms`; code returns config byte only.
- **Impact**: Clients (future XMouseCtrl) parsing the result field would misread it.
- **Fix**: Corrected to `config byte` in TECHNICAL.md (2026-06-16).

### F-03 · HIGH · OPEN — Release pipeline mutates source doc templates in-place
- **File**: scripts/build-release.ps1:lines 42-46
- **Evidence**: `env-replace` runs without `-OutputDir` on `XMouseD.guide`, `XMouseD.readme`, `Install`, `docs/*.md`, `*.md`. Confirmed: `dist/XMouseD-1.0-rc1/` already exists, meaning templates have already been permanently substituted.
- **Impact**: After any `make release`, source doc files contain resolved values instead of `[]($VAR)` / `~ VALUE [NAME]~` placeholders. Subsequent releases reprocess already-substituted files (safe but confusing). `git diff` is noisy; templates cannot regenerate without `git restore`.
- **Recommendation**: Either (a) always pass `-OutputDir ./dist` for release copies and keep source files as templates, or (b) add `git restore` at the end of the release script to restore template files.
- **Status**: Open — requires release workflow decision before fixing.

### F-04 · MEDIUM · VERIFY — Manual GetArgStr() offset `DOSBase + 0x114`
- **File**: src/xmoused.c (parseArguments function)
- **Evidence**: `(GetArgStrFunc)((UBYTE *)DOSBase + 0x114)` — positive offset into DOS library base. Library jump tables are at NEGATIVE offsets in AmigaOS; positive offsets are the library data structure.
- **Impact**: If this offset is wrong, GetArgStr returns garbage and argument parsing produces random behavior. Code reportedly works on V4 hardware, suggesting the offset is correct or a VBCC-specific pragma convention applies.
- **Recommendation**: Verify `0x114 = LVO 46` maps to `GetArgStr` in NDK39 dos.library LVO table. Document why positive offset is used.
- **Status**: Open — verify against vendor/NDK39 LVO table, no fix needed if confirmed correct.

### F-05 · LOW · FIXED — USAGE.md typo "argments"

- **Evidence**: "argments" instead of "arguments".
- **Fix**: Corrected (2026-07-12).

### F-06 · LOW · FIXED — USAGE.md missing STATUS command
- **File**: docs/USAGE.md Command Arguments table
- **Evidence**: `XMouseD STATUS` is implemented in code and documented in CHANGELOG/guide but absent from USAGE.md table.
- **Fix**: Added STATUS row to table (2026-07-12).

### F-07 · LOW · OPEN — Release pipeline runs env-replace on `.\src` unnecessarily
- **File**: scripts/build-release.ps1:line 51
- **Evidence**: No `[]($VAR)` placeholders exist in C source files; the call is a no-op but adds confusion and risk if placeholders are introduced in future.
- **Recommendation**: Remove `. $EnvReplace -Recurse -Force -Path ".\src"` from build-release.ps1 or add a comment explaining it's intentional.
- **Status**: Open — minor, safe to address during next release script review.

### F-08 · LOW · OPEN — Installer `(infos)` clause for executable has no source icon
- **File**: Install (AmigaOS Installer script)
- **Evidence**: `(infos)` inside `(copyfiles)` for the executable looks for `XMouseD.info`. The release archive does not include a program icon (confirmed by archive structure in docs/Next.md).
- **Impact**: Installer may silently skip the `.info` copy or warn user. Not a critical failure but leaves the program without a Workbench icon.
- **Recommendation**: Either add a program `.info` to the archive, or remove `(infos)` from the executable's copyfiles block.
- **Status**: Open.
